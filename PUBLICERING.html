Guide för Skogskolmodellen 10.4-streamlit.1, framtagen 26 oktober 2026.

Du laddar upp modellfilerna till GitHub och låter Streamlit Community Cloud köra appen. När publiceringen är klar får modellen en webbadress som du kan dela med andra. Hela grundförfarandet kan göras i en vanlig webbläsare.

1. Packa upp paketet på datorn

  1. Ladda ned Skogskolmodellen_v10_4_GitHub_Streamlit.zip.
  2. I Windows: högerklicka på ZIP-filen och välj Extrahera alla.
  3. Öppna den uppackade mappen. Fortsätt till den nivå där du ser filen streamlit_app.py.
  4. Kontrollera att samma mapp också innehåller requirements.txt, model_adapter.py, Skogskolmodellen_v10_4.py, input_schema.json, standardscenario.json och webbmodell.html.

Det är innehållet i den uppackade mappen som ska laddas upp till GitHub. Laddar du enbart upp ZIP-filen kan Streamlit inte hitta appens startfil. Paketet är litet och behöver inte delas i mindre ZIP-filer.

2. Skapa ett nytt repository på GitHub

Ett repository är GitHubs projektmapp för kod och dess versionshistorik.

  1. Gå till github.com och logga in.
  2. Klicka på + uppe till höger och välj New repository. Du kan också öppna github.com/new.
  3. Välj ditt konto under Owner.
  4. Skriv skogskolmodellen som Repository name. Om det namnet redan används på ditt konto kan du exempelvis skriva skogskolmodellen-streamlit.
  5. En lämplig beskrivning är: Skogskolmodellen 10.4 – scenarier för skog och klimat.
  6. Välj Public för den enklaste publiceringsvägen. Då blir också modellens källkod offentligt läsbar. Om du vill begränsa insynen i koden väljer du Private och följer även avsnitt 8.
  7. Låt GitHub lämna README, gitignore och licens tomma här. Paketet har redan en README och en gitignore.
  8. Klicka på Create repository.

Detta följer GitHubs dokumentation om att skapa nya projekt [1].

3. Ladda upp filerna

  1. I det nya, tomma projektet: klicka på länken uploading an existing file. Om det redan finns filer väljer du Add file → Upload files.
  2. Öppna den uppackade mappen i Utforskaren.
  3. Markera filerna och undermapparna inne i mappen och dra dem till GitHubs uppladdningsruta. Dra inte med den yttre mappen.
  4. Vänta tills listan med uppladdade filer är färdig.
  5. Skriv exempelvis Lägg till Skogskolmodellen 10.4 för Streamlit som commit-meddelande. En commit är en sparad version i GitHub.
  6. Klicka på Commit changes, eller motsvarande knapp för att spara.

Kontrollera sedan projektets startsida. Filerna nedan ska ligga direkt där, utan att du först behöver öppna ytterligare en mapp:

GitHubs dokumentation beskriver uppladdningsförfarandet [2]. Alla filer i detta paket ligger långt under GitHubs gräns på 25 MiB per fil för uppladdning via webbläsare.

Mapparna tests och .github bör också följa med. De behövs för automatiska kontroller. Appen kan starta även om dessa två mappar saknas. GitHub kan be om särskild behörighet för att lägga till en workflow-fil. Om det händer kan du först publicera appen utan .github och därefter lägga till kontrollflödet genom GitHubs gränssnitt. Ingen sådan behörighet behövs för modellens vanliga filer.

4. Koppla Streamlit till GitHub

  1. Öppna share.streamlit.io.
  2. Skapa ett Community Cloud-konto eller logga in på ditt befintliga konto.
  3. Koppla samma GitHub-konto som äger modellprojektet. Vid en ny koppling visas normalt Connect GitHub account och därefter Authorize streamlit.
  4. Kontrollera att rätt GitHub-användare eller organisation är vald i Streamlits arbetsyta.

För ett projekt under en organisation, exempelvis ett institut, kan den som administrerar organisationen behöva godkänna kopplingen. Den som publicerar appen behöver administratörsbehörighet till GitHub-projektet [3].

5. Publicera appen

  1. Klicka på Create app i Streamlit.
  2. Om frågan om en befintlig app visas, välj Yup, I have an app.
  3. Välj projektet, grenen och startfilen enligt tabellen nedan.
  4. Klicka på Advanced settings och välj Python 3.12. Lämna fältet Secrets tomt. Klicka på Save.
  5. Välj om du vill ange ett eget appnamn under App URL.
  6. Klicka på Deploy och låt installationen bli klar [4].

DITT_GITHUBNAMN är en platshållare. Ersätt det med det användarnamn du ser på GitHub. Om du valde ett annat projektnamn använder du det namnet i stället för skogskolmodellen. Välj den gren som faktiskt syns i GitHub om den heter något annat än main.

Du kan även klistra in länken till streamlit_app.py från GitHub om Streamlit inte hittar projektet i sin lista.

Om du får använda namnet skogsnytta blir adressen https://skogsnytta.streamlit.app/. Detta är ett exempel på önskad adress; namnet har inte reserverats i denna leverans. Streamlit kan annars skapa en annan adress automatiskt.

Första installationen kan ta några minuter. requirements.txt installerar Streamlit, pandas och Node.js-paketet. Du behöver inte själv lägga till packages.txt eller installera Node.js på din dator för denna publicering.

Gör därefter dessa praktiska kontroller:

  1. Ändra arealen till 2 ha. Netto per hektar ska vara oförändrat och totalt netto ska bli cirka 2 316,83 tCO₂, avrundat 2 317.
  2. Välj Jämför skötselmetoder och klicka på Beräkna jämförelsen.
  3. Välj Referenskontroller och klicka på Kör referenskontroller. Kontrollera att 40 utfall redovisas. En beräknad kontroll kan visa en avvikelse mot en studie; det är en del av modellens redovisning.
  4. Välj Original webbmodell. Kontrollera att det tidigare gränssnittet laddas och att du kan ändra ett scenario där.
  5. Hämta ett scenario som JSON och läs tillbaka det i Streamlit-vyn.

Den kompletta verifieringsredovisningen finns i VERIFIERING.md.

7. Dela webbadressen

För att alla med länken ska kunna öppna modellen behöver Streamlit-appen vara offentlig. Öppna appens Settings → Sharing och kontrollera inställningen under Who can view this app. Offentlig åtkomst anges som This app is public and searchable. Du kan sedan kopiera adressen via Share → Copy link [5].

Prova länken i ett privat webbläsarfönster där du inte är inloggad på GitHub eller Streamlit. Om modellen går att använda där är åtkomsten kontrollerad. Offentlig betyder att fler än den avsedda mottagargruppen kan hitta appen.

Du har därefter två separata publiceringar om den tidigare Netlify-adressen också finns kvar: en på Netlify och en på Streamlit. Ändringar i detta GitHub-projekt förs automatiskt vidare till den kopplade Streamlit-appen. En Netlify-publicering uppdateras när den har en motsvarande koppling till sina egna publiceringsfiler.

8. Om du vill ha privat kod och offentlig app

Du kan använda ett privat GitHub-projekt och ändå göra själva Streamlit-appen offentlig. Då behöver Streamlit få åtkomst till det privata projektet under Settings → Linked accounts → Source control. Följ kopplingsstegen där [3].

Appen blir normalt privat från början om källprojektet är privat. Ändra sedan appens delning enligt avsnitt 7 [5]. Besökare kan använda modellen utan att GitHub-projektet blir offentligt. Modellen har samtidigt en nedladdningsbar webbversion, vars beräkningskod levereras till besökarens webbläsare.

9. Uppdatera modellen senare

Streamlit följer den gren som valdes vid publiceringen [6].

  1. Öppna ditt GitHub-projekt och kontrollera att grenen main är vald.
  2. För en liten textändring: öppna filen, klicka på pennsymbolen, ändra och spara med Commit changes.
  3. För en ny modellleverans: packa upp det nya paketet och välj Add file → Upload files. Ladda upp de uppdaterade filerna på samma platser som tidigare.
  4. Spara med ett tydligt commit-meddelande, exempelvis Uppdatera app och modell till nästa verifierade version.
  5. Öppna Streamlit-appen och kontrollera versionen och ett känt scenario.

Streamlit hämtar sparade ändringar automatiskt. Beroendeändringar kan ta längre tid än rena text- och kodändringar. Om appen fastnar, använd Reboot app i apphanteringen och läs loggen.

Om du arbetar i VS Code är motsvarigheten att spara, göra en commit och sedan Push/Sync Changes till GitHub. En lokal sparning i VS Code räcker inte för att uppdatera den publicerade appen.

Motorfilen, webbfilsversionen, indataschemat och standardscenariot ska hållas samstämmiga vid framtida modelluppdateringar. Filen original_hashes.json och referensbaslinjen ska bara bytas efter en avsiktlig, verifierad ny modellversion. Enbart ändringar i Streamlit-gränssnittet kräver ingen ny vetenskaplig modellversion.

11. Förvaltning och tekniska detaljer

Den nya Streamlit-vyn kör beräkningarna på servern genom originalets Pythonanrop till JavaScript-motorn. Vyn Original webbmodell kör sin beräkning i besökarens webbläsare. Samma antaganden och modellmotor används.

JSON-filer kan flyttas mellan vyerna. De två gränssnitten delar inte ett automatiskt synkroniserat scenario. CSV-filerna är semikolonseparerade och UTF-8-kodade med BOM, vilket underlättar öppning i svensk Excel. Om Excel inte delar upp kolumnerna, välj Data → Från text/CSV, avgränsare semikolon och UTF-8.

Känslighetsanalys och källredovisning har samma vetenskapliga begränsningar som version 10.4. Denna leverans innehåller ingen ny kalibrering eller granskning av skogsreferenserna.

Den automatiska kontrollen i GitHub visas under fliken Actions när .github/workflows/kontroll.yml finns på plats. Grönt resultat betyder att de definierade kontrollerna passerat. Dessa kontroller jämför även Streamlit-vyns funktion med beräkningsresultaten. De ersätter inte en vetenskaplig validering av modellens antaganden.
